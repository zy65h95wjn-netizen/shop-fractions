## Validation failures diagnosed

### Cached motion.js

The failed test called `.text()` on an absent cache match. Its wait used an async `waitForFunction` predicate, which this Playwright runtime treated as a truthy Promise before the eventual boolean resolved. The diagnostic directly confirms that `waitForFunction(async () => false)` returns a handle containing `false` instead of polling.

At the premature observation, R12 still controlled the page, R13 was `installing`, and the new cache could be empty. Cache creation is not evidence that `cache.addAll()` has completed. Once installation completed, the exact requested URL `/peach-physics/v8/motion.js` matched both URL-object and string lookups: status 200, response type `basic`, MIME `text/javascript`, and approved content. This was a test timing defect, not an offline script-loading defect.

The corrected release test awaits each observation in an explicit bounded polling loop. It requires a changed, activated controller, the matching active worker, all eight exact URLs, the correct JavaScript response and the approved script hash. It deliberately holds the motion-script HTTP response during installation and asserts that R12 remains in control and incomplete caching is not accepted. It then completes installation, disconnects the browser, reloads and verifies the actual offline fetch body and running motion engine in both renderers. No arbitrary delay is used to establish readiness.

Reproduction: `tests/motion-cache-diagnosis.cjs`; evidence: `tests/motion-cache-diagnosis.json`.

### Retained contact coordinates

The production test page had already run kick, drag and flick scenarios; the reference page had not. R12's `reset()` intentionally retains impact X/Y while clearing pressure/contact/target and waves. The unequal histories left normalized contact positions `(0.3399455982, 0.6876343163)` and `(0.2816153029, 0.6493117893)`. Both had `v=contact=target=0`.

The diagnosis reproduces the mismatch in WebGL and Canvas. All other recorded state is identical and all three rendered frame hashes match. This is unequal inactive state, not changed active behavior.

The regression scenarios now explicitly establish the same character-specific contact coordinates before applying matched input. Full raw-state comparisons still include X/Y, including active contacts; pixel comparisons are retained. Separate reset contracts verify on R12, approved R13.3 and production R13 that reset preserves X/Y, clears active contact/wave state and leaves rendered moving springs unaffected by inactive coordinate changes. No production reset behavior was altered.

Reproduction: `tests/motion-contact-diagnosis.cjs`; evidence: `tests/motion-contact-diagnosis.json`.

### Santa's dormant laugh state

The first deeper offline test expected a dormant timer of 0. R12 initializes and resets `santaLaughTime` to -1; 0 means a laugh has started. The corrected test compares with the captured R12 baseline (-1) and separately checks that automatic motion produces no synthesized Santa laugh audio. No audio behavior changed.

## Release checks

Run from the repository root with Node, Playwright and Chromium installed:

```
node peach-physics/v8/tests/motion-unit.cjs
node peach-physics/v8/tests/motion-regression.cjs
node peach-physics/v8/tests/motion-release.cjs
```

- `motion-unit`: 56 checks for directional response, continuous Auto, filtering, permissions-independent controller state, touch/hidden suspension, stale input, cooldown and budgets.
- `motion-regression`: 90 disabled-feature state/frame comparisons against R12, 90 enabled-mode comparisons against approved R13.3, and 30 reset contracts across all five characters and both renderers. Comparisons cover Natural, Playful and Chaos. Source checks enforce exact controller bytes, approved runtime identity apart from storage restoration, original assets, manifest and icon.
- `motion-release`: 137 checks covering the actual R12-to-R13 upgrade with intentionally delayed precaching; offline WebGL and Canvas; all eight resource URLs; exact cached and offline-served motion bytes; all five custom profiles, audio preferences, framing, normal profile writes, sharing, gesture permission, silent automatic effects and motion settings across offline reloads.

Results are stored alongside each test as JSON. Historical `grab-hold-release.cjs` validates the R11-to-R12 release contract; R13's corresponding promotion contract is `motion-release.cjs`.

These browser checks use Chromium at iPhone-sized viewports. Lance's physical iPhone approval applies to the unchanged R13.3 behavior; no new physical-device result is claimed for packaging, offline upgrades or performance.
